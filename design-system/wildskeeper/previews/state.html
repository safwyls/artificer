State and dialogs

Running, stopped, unreachable — and confirming a loss

Four dots and one dialog carry most of what a console has to say. The dot vocabulary is fixed: ok green for healthy, rune for live activity, mist for stopped, ember for a fault. A destructive dialog names what is lost, and its confirm button repeats the verb.

Unreachable — what to do, not just what happened

Server unreachable

last seen 4m ago

The agent on this host stopped answering. The container may still be running — check the host page, or view the container log for the last thing it said.

Rules

  • A failure state offers the next action. “Unreachable” with no buttons is a dead end.
  • The confirm button repeats the verb and the dialog body names the cost. “Are you sure?” is not a warning.
  • Ember is for faults, not for warnings — a slow tick is accent brass, a crashed server is ember.
