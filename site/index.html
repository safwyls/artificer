Self-hosted game server consoles

The forge behind
your game servers.

Artificer is the codebase behind three server dashboards — Palworld, RuneScape Dragonwilds and Enshrouded. They share a core, so a fix to backups or scheduling lands in all three at once, and each game keeps only the parts that are genuinely its own.

The consoles

Same dashboard, different game

Every console gets power control, scheduled restarts, backups, users and permissions, Discord alerts and a settings editor. What differs is what each game lets a console read and say — so the features below are the ones only that game has.

palcon

Palworld · REST + RCON

The deepest of the three, because Palworld's save file can be read.

  • Player pals, guilds and inventories from the world save
  • Storage and chest search, with world loot behind a switch
  • Paldex, breeding and stat calculators
  • A pal advisor that answers questions about your world
  • Per-player visibility controls

wildskeeper

Dragonwilds · dwbridge mod

The game ships no admin protocol, so commands travel through a UE4SS mod.

  • World metadata read straight from the SPUD save
  • Choose the native Linux build or the Windows build under Wine
  • One-click UE4SS + dwbridge install on the Wine image
  • Player roster and bans from the server log and ini

flametender

Enshrouded · Steam query

Windows-only server run under Wine, with presence from the game's own query port.

  • Live player count and build from the Steam A2S query
  • Role-group passwords assigned by capability, never by name
  • Ban edits queued and applied while the server is down
  • Rolling save archives, extensionless blobs included

The host service

Anvil places the containers

No console holds Docker create rights. One small service does, and it is deliberately blind to games: it knows nothing about Palworld or Enshrouded, only about images it is allowed to run and data directories it owns. Each console registers with its own token, its own data root and its own environment namespace, and can never see another's servers.

Raise a server

A console asks for a container by image, ports and environment. Anvil checks the image against that console's allowlist, creates the data directory and starts it.

Adopt what's already running

Servers deployed by hand are discovered by image family and adopted with their existing token and passwords intact — no retyping, no downtime.

Keep the world on destroy

Unmaking a container is not consent to delete what it was holding. The data directory always survives, and is reported back so you know where it went.

Shared world saves

Some worlds live in a save folder, not on a server

For those, whoever hosts is whoever holds the newest copy — and passing that around a group by hand ends the same way every time: two people play the same evening, and one of them loses it. Reliquary holds the world instead and lends it to one player at a time, with every check-in kept as a version. It runs as its own container, knows nothing about any game, and works for games no console here supports.

One holder at a time

Check out, play, check in. Nobody else can take the world while you have it, and the next player is queued rather than racing you for it.

A companion that finds the folder

A small app on each player's machine spots installed games and their save folders, and moves the saves. Even the scrambled folder names Unreal games generate.

Get it back from whoever's asleep

An admin can ask a holder's companion to check in. It answers next time that machine is online, and the evening they played is not lost.

Raising a server

From wizard to running world

Four hops, none of which need a shell. The numbering is real: each step depends on the one before it.

You fill the wizard

Name, host, ports. The console proposes free ports by checking both its own rows and the containers already on the host.

Anvil places it

It pulls the agent image, makes the data directory, publishes the ports and starts the container with a generated token.

The agent installs the game

On first boot the sidecar runs SteamCMD, seeds the config file with your server name and password, then starts the game as a child process.

The console takes over

Power, logs, config edits, backups and scheduled restarts all run through the agent's authenticated API from then on.

the shortest possible start — one console, no provisioning
services:
  palcon:
    image: ghcr.io/safwyls/palcon:latest
    ports: ["8080:8080"]
    environment:
      DATA_DIR: /data
      JWT_SECRET: <random string>
      ENCRYPTION_KEY: <exactly 32 characters>
      ADMIN_USERNAME: admin
      ADMIN_PASSWORD: <your first-login password>
    volumes: ["./data:/data"]
    restart: unless-stopped

# Swap the image for wildskeeper or flametender — same shape, same variables.
