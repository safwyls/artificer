Deploy on TrueNAS Scale

This is the setup Sampo is developed against. You will create two or three datasets, deploy Ilmari once, deploy one console per game, and raise servers from the dashboard. Nothing here needs the shell except one chown, and even that is avoidable if you get the dataset permissions right the first time.

1. Decide your datasets

Two kinds of storage, and they should not be the same directory:

DatasetHoldsExample
Console dataThe database — servers, users, metrics history — and backup archives. Small./mnt/tank/apps/palcon
Server data rootOne subdirectory per game server: the game install and its world. Large — budget 10 GB per Palworld server./mnt/tank/apps/palcon-servers

Give each console its own pair. Running palcon and wildskeeper on one box means four datasets, which keeps their backups, quotas and snapshots independent.

2. Get ownership right now, not later

TrueNAS apps run as the apps user, uid and gid 568. Every dataset above must be owned by it. In Datasets → Edit Permissions, set owner and group to 568, or from the shell:

TrueNAS shell
sudo chown -R 568:568 /mnt/tank/apps/palcon /mnt/tank/apps/palcon-servers

This is the single most common way a deployment fails. A server data directory owned by root under a container running as 568 cannot be written. SteamCMD does not report that as an error — it exits successfully having installed nothing, and the only symptom you ever see is a server refusing to start because "the game is not installed". If that happens, this is why.

3. Deploy Ilmari

One per host, shared by every console. In Apps → Discover Apps → Custom App, choose Install via YAML and paste:

Custom App — ilmari
services:
  ilmari:
    image: ghcr.io/safwyls/ilmari:latest
    pull_policy: always
    ports:
      - 8820:8820
    environment:
      ILMARI_CLIENTS: '[{"id":"palcon","token":"<32+ random chars>",
        "dataRoot":"/mnt/tank/apps/palcon-servers","envPrefix":"PALAGENT_"}]'
      ILMARI_PUBLIC_HOST: 192.168.1.9    # this box's LAN IP
      ILMARI_DEFAULT_RUN_AS: "568:568"
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock
      # Each dataRoot, mounted at the exact path it is registered as.
      - /mnt/tank/apps/palcon-servers:/mnt/tank/apps/palcon-servers
    restart: unless-stopped

The data root mount is mandatory. Ilmari creates and chowns each server's directory itself. Without the mount it does that inside its own container, Docker creates the real directory on the host as root, and you land in exactly the failure described in step 2. Add one mount line per data root, and add a new one whenever you register another console.

Ilmari runs as root — it holds the Docker socket, and it has to be able to chown directories to the apps user. Do not add a user: line to this app.

4. Deploy a console

Another Custom App. This example is palcon; for the others swap the image and the port, and nothing else changes.

Custom App — palcon
services:
  palcon:
    image: ghcr.io/safwyls/palcon:latest
    pull_policy: always          # redeploy picks up new builds
    user: "568:568"              # must own the dataset below
    ports:
      - 30801:8080
    environment:
      DATA_DIR: /data
      JWT_SECRET: <random string>
      ENCRYPTION_KEY: <exactly 32 characters>
      ADMIN_USERNAME: admin
      ADMIN_PASSWORD: <your first-login password>
      # One-click provisioning. Same token as the ILMARI_CLIENTS entry.
      ILMARI_URL: http://192.168.1.9:8820
      ILMARI_TOKEN: <32+ random chars>
    volumes:
      - /mnt/tank/apps/palcon:/data
    restart: unless-stopped

ENCRYPTION_KEY must be exactly 32 characters and must never change. It encrypts stored server passwords and agent tokens; losing it makes them unrecoverable and every server has to be re-adopted. Back it up with the database.

ConsoleImageSuggested host port
palconghcr.io/safwyls/palcon30801
wildskeeperghcr.io/safwyls/wildskeeper30802
flametenderghcr.io/safwyls/flametender30803

5. First login

Open http://<your-nas>:30801 and sign in with the admin credentials you set. Change the password from the account menu — the environment variable only seeds the first account, and leaving a password in an app spec is worth avoiding.

6. Raise your first server

Press + in the rail and choose Provision a new server. The wizard prefills the host and the data root from Ilmari, and proposes ports that avoid both existing rows and containers already on the host. See Your first server for what each field does.

Ilmari creates the container, the agent installs the game, and the card shows progress. A first Palworld install is roughly 5 GB and takes a few minutes.

7. Ports and collisions

TrueNAS reserves everything below 9000 for the system in its UI validator, which is why the console examples use the 30000+ range. Game ports are published directly and must not collide with each other or with anything else on the box.

GamePublishes
Palworld8211/udp game, 8212 REST, 25575 RCON, 8811 agent
Dragonwilds7777–7778/udp (a contiguous pair), 8811 agent
Enshrouded15637/udp game and query, 8811 agent

The wizard's port proposal handles this for you when it can see the host through Ilmari. If you run two servers of the same game, the second gets a different published set automatically.

The agent port must be published, even though only the console talks to it. A container without it can be discovered but never adopted — there is no address to reach its agent on.

8. External access

Put a reverse proxy or a Cloudflare Tunnel in front of the console's port. If you use Cloudflare Access in front of it, the console can accept that sign-in instead of its own password form — set CF_ACCESS_TEAM_DOMAIN, CF_ACCESS_AUD and CF_ACCESS_ADMIN_EMAILS. Password login stays available either way.

Set COOKIE_SECURE=true once the console is only reachable over HTTPS.

Do not expose Ilmari. It holds the Docker socket and only consoles on the same host need to reach it. If your consoles run on the same box, its port never has to leave the LAN at all.

9. Updating

With pull_policy: always, redeploying an app in the TrueNAS UI pulls the new image and restarts it. TrueNAS will not repull a tag it already has on its own, so an app that looks unchanged after a release usually just needs an explicit update.

Agents update separately, from the console's agent-image action — the console asks Ilmari to recreate that container on a new tag, keeping its ports, volume and environment. The game install and world are on the volume, so nothing is re-downloaded.
