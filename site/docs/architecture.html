Architecture

One Go module, one web workspace, and a rule about which direction dependencies are allowed to point. Everything else follows from that.

The layout

PathWhat lives there
core/The console framework: HTTP API, auth, store, backups, scheduler, collector, the sidecar agent kit, the Anvil client. Knows nothing about any specific game.
games/<game>/One directory per game: its client, its config-file codec, its log or save readers, its agent spec, and any routes only it has.
cmd/The binaries. Each console main is thin wiring: register the game, set the cookie name, hand core its profile.
web/<console>/One React app per console, each with its own theme.
anvil/The host provisioning service. A separate module — it references no console and no game.
deploy/Dockerfiles, one directory per console.

The dependency rules

Checked in CI by scripts/checkbounds.sh, because they are easy to break by accident and expensive to unpick later:

  • core never imports a game. If core needs game-shaped behaviour it takes it as a parameter — a codec, a profile, a hook.
  • Games never import each other. Two games needing the same thing means it belongs in core.
  • An agent never imports its console-side game package. The agent binary has no business linking a console registry, so shared constants like a Steam app id are spelled twice, with a test keeping the copies honest.
  • Anvil references nothing above it. It is game-blind by contract.

How a game plugs in

A game supplies as much or as little as it can. Everything here is optional except the definition itself:

SeamWhat it gives the console
game.DefinitionId, display name, default port, feature list, and the client constructor.
game.ConfigCodecReading and writing the game's settings file, in its own grammar.
game.SaveLayoutWhich file is the world, what belongs in an archive, and how to tell a torn save from a whole one.
api.ProvisionProfileEverything the wizard interpolates: agent name, image, env prefix, ports, mount path.
api.RosterSourceA player roster read from the save, where one exists.
Contributed routesEndpoints only this game has — palcon's pals and storage views, wildskeeper's world page.
agent.GameThe agent-side spec: app id, config path, save discovery, launch profiles, and what to do before each start.

A game that declares none of the optional seams still gets power, backups, scheduling, users and alerts. That is the floor.
