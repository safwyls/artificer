Introduction

Sampo is one codebase that produces three self-hosted game server consoles. You run whichever ones you need — they are separate images and separate deployments — but they are built from the same core, so they behave the same way and get fixed at the same time.

palconPalworldghcr.io/safwyls/palcon
wildskeeperDragonwildsghcr.io/safwyls/wildskeeper
flametenderEnshroudedghcr.io/safwyls/flametender

Which console do you want?

Pick by game. Each console manages exactly one game, and running two of them side by side on the same host is normal and supported.

ConsoleGameHow it talks to the server
palconPalworldREST API, falling back to RCON
wildskeeperRuneScape DragonwildsA UE4SS mod — the game ships no admin protocol
flametenderEnshroudedSteam A2S query for presence; no command protocol exists

What all three give you

  • Power control — start, stop and restart, with the game asked to save first where it can.
  • Scheduled restarts with in-game warnings, and a crash watchdog.
  • Backups — zip snapshots of the world on a schedule, with retention.
  • Users and permissions — per-account rights over power, moderation, settings and each data view.
  • Discord alerts for reachability changes, joins and leaves, and restart notices.
  • A settings editor for the game's own config file, with the game's grammar respected.
  • One-click provisioning through Ilmari, including adopting servers you already run.
  • Optional single sign-on through Cloudflare Access, alongside password login.

What differs

Only what the game itself makes possible. Palworld exposes a readable save file, so palcon can show pals, guilds, inventories and storage. Dragonwilds exposes nothing at all until you install a mod, so wildskeeper ships one. Enshrouded answers a Steam query but takes no commands, so flametender is honest about which buttons cannot exist and says why.

Features a game cannot support are not hidden — they answer with a reason. A command that has nowhere to go returns 501 and names where the ability actually lives.

The pieces you deploy

A working setup has two or three moving parts:

  • The console — the web dashboard you log into. One per game.
  • A sidecar agent — one per game server, sharing its install volume. It installs the game, runs it, and serves saves, config and logs over an authenticated API. See Sidecar agents.
  • Ilmari — optional but recommended, one per host. It is the only component holding Docker rights, and it is what makes the Raise-a-server wizard work. See Ilmari.

Without Ilmari the consoles still work; you register servers by hand and deploy their stacks yourself. Without an agent a console can still drive a game over its network protocol, but loses file access — saves, config editing and backups.
