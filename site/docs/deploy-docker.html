Deploy with Docker

Everything here works on any host with Docker and Compose — a VPS, a home server, a NUC in a cupboard. The only real difference from the TrueNAS walkthrough is that you choose the user and the directories yourself.

1. What you need

  • Docker Engine with the Compose plugin.
  • A directory you control for persistent data.
  • Enough disk for the games: roughly 5 GB per Palworld or Enshrouded server, more with backups.
  • The UDP ports for whichever games you run, open to players.

2. Lay out the directories

shell
mkdir -p ~/artificer/{data,servers}
cd ~/artificer

# Run everything as yourself rather than root; note the ids.
id -u; id -g

data/ holds the console database. servers/ is the data root — Anvil creates one subdirectory per game server inside it.

3. Generate the secrets

shell
# JWT signing secret — any length, keep it private
openssl rand -hex 32

# Encryption key — must be EXACTLY 32 characters
openssl rand -hex 16

# Anvil token — shared between anvil and the console
openssl rand -hex 24

ENCRYPTION_KEY must be exactly 32 characters and must never change once servers are registered. It encrypts agent tokens and server passwords; rotating it orphans every stored credential. openssl rand -hex 16 gives exactly 32 hex characters, which is why it is 16 and not 32 there.

4. Write the compose file

This runs one console and Anvil. Replace the placeholder secrets, the public host and the uid pair with your own.

~/artificer/docker-compose.yml
services:
  palcon:
    image: ghcr.io/safwyls/palcon:latest
    user: "1000:1000"            # your id -u : id -g
    ports:
      - "8080:8080"
    environment:
      DATA_DIR: /data
      JWT_SECRET: <openssl rand -hex 32>
      ENCRYPTION_KEY: <openssl rand -hex 16>
      ADMIN_USERNAME: admin
      ADMIN_PASSWORD: <first-login password>
      ANVIL_URL: http://anvil:8820
      ANVIL_TOKEN: <shared token>
    volumes:
      - ./data:/data
    restart: unless-stopped

  anvil:
    image: ghcr.io/safwyls/anvil:latest
    # root: it holds the docker socket and chowns data directories
    environment:
      ANVIL_CLIENTS: '[{"id":"palcon","token":"<shared token>",
        "dataRoot":"/home/you/artificer/servers","envPrefix":"PALAGENT_"}]'
      ANVIL_PUBLIC_HOST: 203.0.113.10   # how players reach this host
      ANVIL_DEFAULT_RUN_AS: "1000:1000"
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock
      # The data root, at the SAME path it is registered as above.
      - /home/you/artificer/servers:/home/you/artificer/servers
    restart: unless-stopped

The dataRoot path must be identical on both sides of that mount, and identical to what ANVIL_CLIENTS declares. Anvil creates each server's directory and chowns it to runAs; if the path is not mounted it does that inside its own container, Docker creates the real one as root, and the agent cannot write its install. The failure is silent — SteamCMD exits 0 having downloaded nothing.

Note that Anvil is not published to a host port here. The console reaches it by service name on the compose network, which is exactly as much exposure as it needs.

5. Bring it up

shell
docker compose up -d
docker compose logs -f palcon

Then open http://<host>:8080 and sign in. The Raise-a-server wizard appears once the console can reach Anvil; if it is missing, the console's logs will say why.

6. Raise a server

Press +, choose Provision a new server, and fill in a name. The wizard proposes ports and the data directory; the agent installs the game on first boot. Details of each field are in Your first server.

You do not write an agent compose file yourself — Anvil creates that container. If you would rather deploy it by hand, the wizard also generates a stack you can paste, and the console will adopt it once it is running.

7. Running more than one game

Add another console service and another Anvil client entry. Each console needs its own token, its own data root, its own env prefix, and its own mount into Anvil.

adding wildskeeper
wildskeeper:
  image: ghcr.io/safwyls/wildskeeper:latest
  user: "1000:1000"
  ports: ["8081:8080"]
  environment:
    DATA_DIR: /data
    JWT_SECRET: <its own>
    ENCRYPTION_KEY: <its own, 32 chars>
    ANVIL_URL: http://anvil:8820
    ANVIL_TOKEN: <its own>
  volumes: ["./data-wk:/data"]
  restart: unless-stopped

# and in ANVIL_CLIENTS, a second entry:
# {"id":"wildskeeper","token":"...","dataRoot":"/home/you/artificer/wk-servers",
#  "envPrefix":"WKAGENT_"}
# plus its mount on the anvil service.

Consoles never see each other's servers: Anvil scopes discovery by ownership label and image family, and each console filters again on its own agent family.

8. TLS and a reverse proxy

Put Caddy, Traefik or Nginx in front of the console port and terminate TLS there. With Caddy the whole configuration is two lines:

Caddyfile
palcon.example.com {
  reverse_proxy localhost:8080
}

Then set COOKIE_SECURE=true on the console so the session cookie is only sent over HTTPS. Leave it unset for plain-HTTP LAN deployments, which are a legitimate way to run this.

9. Backing up

Two things matter, and they are small:

  • data/ — the database, plus any backup archives the console has taken.
  • The secrets — ENCRYPTION_KEY above all. Without it the database's stored credentials cannot be decrypted.

The game installs under servers/ are large and completely replaceable; only each server's world directory inside them is worth archiving, and the console's own backup schedule already does that.

10. Updating

shell
docker compose pull
docker compose up -d

Agents are updated from the console instead — the agent-image action asks Anvil to recreate that container on a new tag, preserving its ports, volume and environment. The game install lives on the volume, so nothing is downloaded again.
